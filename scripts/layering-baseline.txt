# Kernel module dependency edges: the census scripts/check-layering.sh
# ratchets.
#
# Each row is `<from module> <to module> <occurrences>`: how many times a file
# under `src/kernel/<from>` names `crate::kernel::<to>::` in code (line
# comments stripped, self-references skipped).  The gate fails when a count
# rises, when a row shrinks without the census being re-recorded, or when the
# tree has an edge no row mentions — so a new dependency between two modules
# has to be added here on purpose.
#
# Re-record with `sh scripts/check-layering.sh --record` in every change that
# moves an edge.
#
# Two directions are wrong on purpose and are expected to reach zero:
#
#   * `block` naming anything else — it is the layer the disk drivers and the
#     filesystem both build on, so it must stay at the bottom.
#   * `drivers` naming `fs` — a driver hands a found device over through
#     `kernel::block::publish_device`; it does not know who consumes it.
#
# The cycles the census still shows — `fs` <-> `process`, `process` <-> `smp`,
# `process` <-> `sync`, `memory` <-> `fs` — are the debt the layering cuts are
# working down.  The counts are the finish line for each cut.
#
